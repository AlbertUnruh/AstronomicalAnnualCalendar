# Specification

So you want to use this project to generate the astronomical annual calendar without data from AstroWin32?

In this document, I show you how any custom files have to be built to be valid.


> [!NOTE]
> This file will get replaced by a command for autogenerated specifications.
> This is done to allow the project to support multiple parsers.
> The command is ``python AstronomicalAnnualCalendar specification AstroWinParser`` for this specification.</br>
> Autogenerated specifications via cli will be implemented soon™.


### The Header/Metadata
The first line in the file contains all the metadata.

It has to match the following RegEx:
```regexp
^Ort:\s*(?P<place>[^,]+),\s*(?P<coordinate>(?P<lat>((?P<degree_lat>\d{1,2}|[0-2]\d{2}|3[0-5]\d|360)°((?P<minute_lat>\s?([0-5 ])?\d)'(\s?(?P<second_lat>(([0-5 ])?\d|60)(\.\d+)?)\")?)?\s?([NS])))(\s*,\s*)?\s+(?P<lon>((?P<degree_lon>\d{1,2}|[0-2]\d{2}|3[0-5]\d|360)°((?P<minute_lon>\s?([0-5 ])?\d)'(\s?(?P<second_lon>(([0-5 ])?\d|60)(\.\d+)?)\")?)?\s?([EWO]))))\s*(\sÄquin:\s*(?P<equinox>-?\d+(\.\d+)?),\s*geozentrisch)?,\s*DeltaT\s?=\s?(?P<delta_t>-?\d+(\.\d+)?)\s?(?P<delta_t_unit>\w+)$
```

> *Depending on the flavor of RegEx I have another variant for you:*
> ```regexp
> ^Ort:\s*(?<place>[^,]+),\s*(?<coordinate>(?<lat>((?<degree_lat>\d{1,2}|[0-2]\d{2}|3[0-5]\d|360)°((?<minute_lat>\s?([0-5 ])?\d)'(\s?(?<second_lat>(([0-5 ])?\d|60)(\.\d+)?)\")?)?\s?([NS])))(\s*,\s*)?\s+(?<lon>((?<degree_lon>\d{1,2}|[0-2]\d{2}|3[0-5]\d|360)°((?<minute_lon>\s?([0-5 ])?\d)'(\s?(?<second_lon>(([0-5 ])?\d|60)(\.\d+)?)\")?)?\s?([EWO]))))\s*(\sÄquin:\s*(?<equinox>-?\d+(\.\d+)?),\s*geozentrisch)?,\s*DeltaT\s?=\s?(?<delta_t>-?\d+(\.\d+)?)\s?(?<delta_t_unit>\w+)$
> ```

> [!NOTE]
> The regex can be found at ``AstronomicalAnnualCalendar.regex.METADATA_REGEX``


### Planet/Sun Data
The planets and sun are a bit more complicated and don't have one simple RegEx.

Each object follows the same structure inside the file:
```text
NAME
FIELDS MATCHING REGEX FROM TABLE BELOW
DATA MATCHING POSITIONS
[...]
DATA MATCHING POSITIONS
```
> [!IMPORTANT]
> **Before** and **after** every object an **empty line** is required!


#### Fields
| header       | description                                                     |
|--------------|-----------------------------------------------------------------|
| name         | the name of the field                                           |
| type         | how it should be structured                                     |
| regex        | the regex the title has to match                                |
| length       | how long the data is (max)                                      |
| offset       | the offset at which the data is extracted                       |
| required for | where the field is used <br/>"-" = nowhere<br/>"*" = everywhere |

How are ``length`` and ``offset`` used?
> The data is extracted from the range [``i - length + offset``,``i + offset``] with ``i`` being the end position of the matched regex title.

| name                            | type                                                                 | regex                   | length | offset | required for |
|---------------------------------|----------------------------------------------------------------------|-------------------------|--------|--------|--------------|

> [!NOTE]
> To extract the correct regex from the table, you have to copy everything between the `` whilst viewing the raw file.</br>
> *Note that `time` for example has a space after "UTC".*

> [!IMPORTANT]
> Any pipes (``|``) are not meant to be escaped in the regex! They are only escaped in order to keep the markdown-table correctly formatted!
